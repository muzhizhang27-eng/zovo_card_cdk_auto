# 卡密与账单查询修复验收

2026-10-28，Asia/Shanghai。公开站点：`https://cdk.lanting.live`。

卡密查询已上线修复。用户提供的两张样本分别返回已使用、未使用，单张 API、批量 API 和真实网页结果一致。账单查询的默认无效依赖、刷新错误吞没、账单获取失败被显示成无记录等问题已修复；生产保存的两个样本凭证仍被 ChatGPT 拒绝，其中明确返回 `token_revoked`。有效新 Session 的真实账单成功查询尚待持有人重新登录后验收，不能据此宣称账单成功路径已完成实测。

## 原因与实现

- 公开兑换库的 `cd_keys`、`cardplatform_cdk_codes`、`recharge_tasks` 均为空。旧查询依赖本地库存及受原设备绑定约束的兑换令牌，不能可靠查询其他实例发出的码；并且未解包上游 `data`，部分上游错误最终变成“未找到”。
- 新增独立 `cdk-lookup.service`，以管理实例的身份只读打开管理库，使用已有所有者 Key 执行卡密和订单 GET 查询。只监听 Unix socket `/run/cdk-lookup/lookup.sock`，公开进程不获得 Key、不读取管理库、不复制库存。
- 上游搜索结果必须与请求的完整码一致才返回摘要，拒绝前缀、掩码或其他码的匹配；只返回状态、套餐及受限订单摘要，不返回卡号、Session、兑换令牌或 Key。上游失败返回查询暂不可用，不伪装成未找到。
- 不再根据绑定邮箱推断卡密已使用。保留旧部署模式时，修复兑换结果的 `data` 解包；查询页补上传原设备标识。
- 账单只在显式配置 `ACCOUNTHUB_BASE_URL` 时调用该服务，默认直接查 ChatGPT。保留刷新错误，区分凭证撤销、凭证失效和上游不可用；支持含 Access Token 的真实 Session JSON，Session Token 为可选刷新凭证。
- 订阅成功而账单明细失败时返回并展示警告，避免显示“无付款账单记录”。账单外链限制为可信域名及其子域名。

## 部署与回退

- 公开版本：`/opt/cdk-recharge/releases/20261028-query-repair`，由 `/opt/cdk-recharge/current` 选择。
- 查询版本：`/opt/cdk-lookup/releases/20261028-query-repair`，由 `/opt/cdk-lookup/current` 选择，独立于公开站后续版本切换。
- 查询单元模板：`deploy/cdk-lookup.service`。Linux amd64 / CGO 构建 `backend/cmd/cdk-lookup` 后安装到查询版本目录。公开环境仅增加 `CDK_LOOKUP_SOCKET=/run/cdk-lookup/lookup.sock`。
- 查询服务只读配置来源：`/var/lib/cdk-admin/cdk_recharge.db`。所有者 Key 或源站变更后，重启查询服务使配置生效。
- 公开后端基于原公开版本源代码构建，仅叠加查询/账单相关文件，未引入管理后台迁移或更改管理实例。前端使用当前工作区通过完整检查的构建，保留旧静态资源哈希，兼容已打开的浏览器标签页。
- 备份：`/var/backups/cdk-recharge/20261028-query-repair`，0700，含原环境文件、版本指向、Nginx 配置与 SQLite 在线备份。前版为 `20261022-public-cdk`。
- 回退时恢复原环境文件与公开版本指向，重启 `cdk-recharge`，停用 `cdk-lookup`，保留全部生产交易与绑定。不要用上线前数据库覆盖上线后的数据。
